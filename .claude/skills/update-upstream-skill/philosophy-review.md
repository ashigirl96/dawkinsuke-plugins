# 思想への影響の評価

upstream の旧版から新版への変更が、`docs/philosophy/<対象>.md` にまとめた作者の思想を変えるかを評価する。対象・`<submodule>`・`<旧版>`・`<新版>`・範囲は、呼び出した側から渡される。

読むだけで、ファイルは書き換えない。

## 1. 今の思想を読む

`docs/philosophy/<対象>.md` を全文読み、`##` と `###` の節ごとに、何を主張しているかを 1 行で控える。

## 2. 変わったものを読む

`git -C upstream/<submodule> diff --name-status <旧版> <新版> -- <範囲...>` で、足された・消された・変わった・移ったファイルを挙げる。skill、playbook、agent、docs、README、CHANGELOG のどれも含める。

- 変わったファイルは `git -C upstream/<submodule> diff <旧版> <新版> -- <ファイル>` で差分を読む。
- 足されたファイルは `git -C upstream/<submodule> show <新版>:<ファイル>` で全文を読む。
- 消されたファイルは `git -C upstream/<submodule> show <旧版>:<ファイル>` で、何がなくなったかを読む。

完了条件: 一覧のすべてのファイルを読んだ。

## 3. 節ごとに判定する

文書の節ごとに、次のどれかを付ける。

- **変わらない**: 主張に触れる変更がない。
- **補強**: 主張を支える根拠が増えた。
- **揺らぐ**: 主張と食い違う変更がある。
- **覆る**: 主張が成り立たなくなった。

どの節にも当てはまらない考えが出てきたら、**新しい考え**として別に挙げる。

小さな変更も積み重ねで見る。1 つずつは言い回しの調整でも、同じ向きの変更が複数のファイルにそろっていれば、まとめて 1 つの変化として判定する。たとえば、文書が中心に置く手順を複数の skill がそろって省き始めた、文書が例に挙げた skill が消えた、`CHANGELOG.md` が方針の転換を書いている、といったもの。言い換えや typo の修正のように主張に触れない変更は「思想に触れない」にまとめる。

根拠には、新版のファイルと行、その引用、文書側の該当する文を並べる。

完了条件: 文書のすべての節に判定がある。手順 2 のすべてのファイルが、どれかの節の根拠、新しい考え、思想に触れない、のどれかに入っている。

## 4. 返す

次の順で返す。

1. 一番重い判定と、その理由を 1〜2 文で。
2. 節ごとの判定の表。列は「節の見出し」「判定」「根拠」。
3. 新しい考えの一覧と、その根拠。
4. 「揺らぐ」「覆る」「新しい考え」のそれぞれについて、文書の直し案。文書冒頭の書き方に従い、作者が書いたことと解釈を分け、解釈には「解釈:」と付ける。
5. 「思想に触れない」としたファイルの数と一覧。
