# ADR.md の形式

fork の `ADR.md` は、決定を上から下へ積んでいく 1 つのファイル。新しい決定は末尾に足す。

## テンプレート

```md
---
upstream: skills/engineering/tdd
own: [naming-ja.md]
---

# tdd の fork

## テスト名を日本語にする

matt は英語の it 文を例に使っている。自分の repo はテスト名を日本語で書くので、例と指示を日本語にし、命名例を `naming-ja.md` に足した。

## seam を合意するときに捉えるものを添える

matt は seam の一覧だけを確認させる。どの seam が何を捉えるかを確認しないと、テストの漏れに後から気づくので、各 seam に 1 行の説明を足させた。
```

## frontmatter

- `upstream`: submodule の中の、元のスキルのパス。
- `own`: fork で足したファイルの一覧。足したファイルがなければ `own: []` と書く。

## 決定 1 つの書き方

1 つの決定は、`##` の題と 1〜3 文の本文でできている。

- **題**: 何をどう変えたかを、短い動詞句で書く。「テスト名を日本語にする」のように書き、「命名について」のような話題名にはしない。
- **本文**: 次の 3 つをこの順に書く。
	1. matt はどうしているか。
	2. 何に変えたか。
	3. なぜ変えたか。

理由は省かない。`/update-matt-skill` で upstream と衝突したとき、どちらを取るかは理由で決まる。

## 今 有効な決定だけを置く

`ADR.md` には、今の fork に当たっている決定だけを置く。決定を変えたら、その `##` を書き直す。やめたら、その `##` を消す。superseded のような印を付けて古い決定を残すことはしない。`/update-matt-skill` は `ADR.md` の決定をすべて当て直すので、無効な決定が混じっていると、それまで当ててしまう。過去の経緯は git の履歴で追う。
