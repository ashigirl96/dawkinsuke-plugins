Call the Skill tool twice, for "grilling" and "domain-modeling".

Once the user confirms the shared understanding and the outcome is something to build, judge whether the work fits in a single fresh context window. State the evidence first: the modules it touches and the tracer-bullet slices you expect. Then, without asking, call the Skill tool for "to-spec". If the work doesn't fit, call it for "to-tickets" next, in the same context.

Your job ends once the issues are published; the build starts later, in a fresh session.
