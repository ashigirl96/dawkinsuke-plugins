最初に Skill tool で `writing-for-agents` を呼ぶ。文書の書き方はそれに従い、この手引きはその上に重ねる。食い違うところは、この手引きが勝つ。

## 言葉

- **部品スキル**: 1 つのことだけをし、他のスキルやプレイブックから組み合わされる前提のスキル。流れ全体を握らない。
- **プレイブック**: ある意図（設計したい・バグを調べたい など）に対し、部品スキルを呼ぶ順番を書いた手順書。repo の `.claude/skills/play/` の下に `.md` で置き、振り分け役の `/play` だけが読む。使うたびに書き足して育てる。

## writing-for-agents の上書き

この環境には skill-chain の mod があり、プレイブックや呼び出し元のスキルの本文が名指しした手動専用のスキル（`disable-model-invocation: true`）の Skill tool の呼び出しを通す。そのため `writing-for-agents` の次の 2 つは、ここでは成り立たない。

- 「手動専用のスキルは他のスキルから呼べない」: プレイブックから呼べる。部品スキルは手動専用のまま名指しして呼ぶ。
- 「振り分け役は案内するだけで、スキルを起こせない」: `/play` は選んだプレイブックの手順どおりに部品スキルを実際に呼ぶ。

プレイブックから呼ぶときに skill-chain が通すのは、次を満たす呼び出し。判定の全体は [skill-chain の README](../../mods/skill-chain/README.md) の「判定」にある。

- 呼ぶ名前が、呼び出し元のスキル（`/play`）のディレクトリの `.md`（プレイブックを含む）に単語として書いてある。そのディレクトリの `.md` は実行中に書き出したものも根拠に数えられるので、プレイブックは手で書いて置き、実行中には書き出さない。
- 呼ぶスキルが、同じ repo の `.claude/skills/` か、dawkinsuke の置き場所にある。user の `~/.claude/skills/` のスキルは呼べない。

## 書式

1 本のプレイブックは 1 つの意図を扱う。冒頭の 1 段落に、どんな依頼のときに選ぶかを書く。`/play` はこの段落で選ぶ。

続けて手順を番号付きの並びで書く。

- **手順 1 つが todo 1 つ。** 実行時、model は手順をそのままの順で todo に写して進める。
- **飛ばす手順も書く。** 条件で要らない回がある手順は「〜なら」と条件を添えて書いておく。当てはまらない回は、その todo を消さずに `skip: <理由>` として残す。
- **部品スキルは「Skill tool で `<name>` を呼ぶ」とだけ書く。** 渡すものがあれば「Skill tool で `<name>` を `<引数>` で呼ぶ」。置き場所の path、SKILL.md を Read させる指示、部品スキルの中身の写しは書かず、名前だけで呼ぶ。
- **プレイブックが持つのは、順番・分岐・手順の間の受け渡しだけ。** 1 つの作業の中身は部品スキルに置く。repo の外の道具のコマンド（`monica task` など）が要るなら、それを包む部品スキルを作って名前で呼ぶ。
