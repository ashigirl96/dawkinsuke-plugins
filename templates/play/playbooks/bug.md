# バグってそう

挙動がおかしい・壊れていそう・遅い（「〇〇がバグってそう」）という依頼で選ぶ。原因を突き止めて issue に残し、直す作業を Bench に渡して PR まで進める。

1. Skill tool で `diagnosing-bugs` を呼ぶ。再現と原因の特定まで進め、ここでは直さない。
2. 原因がバグでなかった（仕様どおり、手元の環境のせいなど）なら、分かったことを伝え、残りの手順をすべて `skip:` にして止まる。
3. `ready-for-agent` ラベルを付けた issue を出す。本文には、再現の手順、突き止めた原因、直し方の見込み、回帰を捕まえるテストの継ぎ目だけを書く。
4. Skill tool で `fork-to-bench` を、3 の issue の URL と次の prompt で呼び、止まる。

   ```text
   /tackle issue は取りに行かず、この会話で突き止めた原因から直す。終わったら、/play の todo の残りの手順に進む。
   ```

5. （新しい Tab で）Skill tool で `pr` を呼んで PR の本文を書き、PR を出す。本文で 3 の issue を `Closes #<番号>` でつなぐ。
